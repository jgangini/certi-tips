# Local Codex Policy for CertiTips

This file supplements the global policy with repository-specific rules. The root README presents the product and courses; contributor instructions belong in docs/courses.md, service operations in service READMEs, and executable checks in [validation.md](validation.md). Experiments and detailed audits belong in ignored output/.

## Source and runtime boundaries

- CertiTips publishes Spanish study guides at /certitips/ in jgangini/certitips. Use Node.js 24, the existing Markdown build and shared browser modules. CertiQuiz and CertiChat are independent optional APIs; do not import server code into browser/build code or add a frontend framework.
- data/catalog.json is the course/page inventory. data/<code>/ is the single course source directory: NN_name/NN_name.md and its img/ contain course text and images, alongside questions.json, coverage.json and authoring specifications. assets/icons/ holds global reusable icons, medals and favicons, regardless of which course introduced them. Preserve Lucide's manifest, exact geometry and ISC AND MIT notices. Preserve user-provided originals in data/CDMP-DMF/diagram-sources/ without changing their bytes or inventing a license.
- Derive numbered module names from modules followed by resources; overview is 00_empieza_aqui. contentDir and route use the course code; page.file locates the Markdown independently of its public slug. Stable course.id, page slugs, question IDs and source IDs preserve progress and evidence. Publish only current code/module routes, with overview/ as the course entry; do not generate legacy aliases or redirect pages. Keep section fragments working.
- CertiTube is independent of course banks: data/certitube/<videoId>/<videoId>.md and optional img/ are its only sources. Publish only reviewed published cards; exclude drafts from pages, search, images and corpus. /certitips/certitube/ opens the latest incorporation by stable addedAt, not YouTube publication date. Keep the ordered video carousel to the right on desktop and below the player on mobile; do not restore the fixed sidebar, menu toggle or Biblioteca. The compact player-card header copies Cognee's shared format and shows the reviewed video title. Inside it show player, red compact Resumen, one scrolling chapter row with sentence-case names and Cognee's exact arrows, one selected explanation with red title, and Recursos relacionados. Use the supplied link icon, compact unindented resource rows and theme foreground text. Omit Caso de uso, Arquitectura, duplicate outer headings/leads and permanent playback actions. Follow native playback/seek at 500 ms only while playing and visible, without seeking again, vertical scrolling or history changes. Animate explanation height/text changes for 240 ms and cancel prior transitions; honor reduced motion. Keep registered time anchors and complete corpus evidence, courseId site, canonical URLs and the 3,000-character evidence limit including title/date context. Header app links remain square accessible icons just before Search, alongside retained hero buttons. Search video icons are blue. See docs/certitube.md.
- Resolve contentDir beneath data/; do not recreate a parallel content/ tree. The site publishes only catalog-listed modules and their img/ assets, not the entire data/ directory. Keep CertiQuiz's Docker/deployment allowlist restricted to catalog and question banks.
- CertiQuiz discovers banks through catalog.courses[].questionBank. Author each bank once at data/<code>/questions.json and register it as <code>/questions; never maintain a second bank or copy it manually to the VPS. Preserve GitHub refresh, last-valid-catalog fallback and existing-room snapshots. Before publishing any catalog/bank or changing the API contract, run `npm run check:certiquiz` (Python 3.12, no packages) plus build/test/check. The checker must reuse services/certiquiz/app/catalog.py; do not duplicate the API schema in another validator. Keep the check mandatory in Pages CI and the CertiQuiz Docker build. A rejected bank must block publication/build, not disable validation or replace the live catalog. See services/certiquiz/README.md for limits; practice availability still requires a quiz.md source.
- dist/ is generated and replaced on build. output/, graphify-out/, caches and .private/ are not published sources. Keep transcripts outside this repository. data/certichat-graph.json is the public projection, not another lesson collection; native Cognee stores and credentials remain private.
- Corpus documents include introductions, anchored sections and explained questions, so their count exceeds the Markdown count. Source-file moves alone do not reduce index size. Reuse an index only when the complete IDs, titles, course IDs and text hashes match; resolve citations from the current validated manifest. Never modify open native stores to change URLs.

## Course editing

- Address the learner directly in Spanish. Catalog metadata supplies H1; chapters use H2/H3. Keep examples, exercises with closed details solutions, sources, glossary and practice in the established shared layout. Every technical H2 needs a specific teaching graphic whose mechanism matches the lesson, not a generic row of text cards.
- Internal links use {{base}} plus the public course code and slug. Module images use img/name.svg or img/name.png beside the Markdown. A heading change changes its anchor: update all references and rebuild/check. Keep image title/description, alt text and caption coherent; the caption explains meaning rather than repeating the title.
- Practice pages use exactly Práctica and Pon a prueba lo que entiendes as page metadata. The entry and results use the red PRÁCTICA eyebrow and compact CertiQuiz heading; the entry keeps its 4px red top border, question/domain counts and right-aligned Comenzar button below a separator. Disable Siguiente until an option is selected. Results show the score, a question table and neutral per-area totals, with reset/exit controls at the top right; both controls confirm before clearing an attempt. Do not restore removed advice, follow-up links or bottom actions. Truncate question rows with ellipsis and expose their full text on hover; clicking opens read-only answer detail with Resumen beside Siguiente and no duplicate answer-status line.
- Questions have four stable options, one correct answer, its explanation and a real section reference. When a supplied quiz.md is the source, translate the complete question, ordered alternatives and Rationale; use Correct Answer, never Selected Answer. Do not replace the rationale with an original summary or invent explanations for distractors: their explanation string may be empty. Give translated questions new stable IDs tied to source numbering and keep source hash/mapping privately. Six questions per technical module remains the default for original banks; a source-sized bank declares exact questionCounts for every technical module in the catalog, at least two per domain. Keep two per module per attempt and preserve the original completed attempt during review. Course sampling and study targets are not official exam weightings or pass marks.
- Data Management Fundamentals (CDMP-DMF) is the DAMA applied course, not an Oracle certification. Its titles and navigation capitalize significant words, leaving articles/prepositions/conjunctions lowercase except at the beginning. Use full official product names in prose, diagrams and questions, without shortening them to AIDP, OAC, EDM or OCI; preserve technical identifiers and URLs exactly.
- Before changing Oracle capabilities, research both Slack product discussion and current public Oracle documentation, release notes and lifecycle notices. Record date, evidence, scope and status privately: available, Preview, implemented extension or announced. Preview is usable within documented scope; an announcement is not availability. Published lessons cite public sources, use fictional cases and explain actual constraints beside the capability.
- Consult supplied DAMA material selectively; book/chapter/page traceability stays in .private/, never the public lessons, diagrams, questions or coverage. Keep instructor agendas, duration estimates and internal course-selection policy out of learner content. Governance centers on Oracle AI Data Platform and Oracle Autonomous AI Lakehouse; do not recommend standalone OCI Data Catalog for new designs. Distinguish catalogs, source identities and policies; never imply automatic synchronization or propagated authorization without evidence.
- Verify each exam edition/language before changing exam numbers or conditions. The October 2026 review confirmed the 40-question/60-minute/65% values publicly for the Japanese 1Z0-1085-26-JPN and 1Z0-1122-26-JPN variants, not independently for every language. Do not promote that historical evidence into a universal verification claim.

## Shared interface components

- El menú de grupos pasa al botón cuadrado hasta 1360 px para evitar solapamiento con la marca. El menú del curso inicia desplegado en escritorio; su botón permanece en el encabezado, refleja aria-expanded y abre/cierra con clic. Al abrir Grupos de cursos o, solo mientras ese botón compacto esté activo, hacer clic en el contenido, pliega el menú lateral; al plegar/desplegar, mover lateral y contenido suavemente y respetar reducir movimiento. Conservar la preferencia de plegado entre lecciones y el panel superpuesto existente en móvil. El área de lectura de cursos usa un acabado glass y el encabezado de lección se limita a 900 px. Con CertiChat abierto, CertiTube no anima el desplazamiento del contenido al cambiar de video.
- CertiQuiz inicia su ruta de navegación 20 px bajo el encabezado, a la misma altura de Cognee en escritorio, sin añadir margen superior a welcome. La separación bajo esa navegación es de 24 px, igual que el gap entre las tarjetas de roles.
- Borrar conversación depende de la carga del componente y de operaciones en curso, no de verified. El preview borra solo su historial local después de la confirmación existente; la vista conectada mantiene DELETE /api/conversation y conserva mensajes si el servidor falla. No reiniciar cuotas ni debilitar las comprobaciones de envío. El SVG de envío pasa a rojo en hover en ambos temas, incluido el campo vacío, conservando su contorno y anulando únicamente el filtro gris inline durante hover.


- Global Search keeps its default course/video listing and searches the published Markdown corpus lazily; reuse the current safe source URLs and the supplied CertiTube SVG. Preserve relevance, whole-word acronyms, real section/time destinations and metadata fallback on failed content loading.
- La lectura de los cursos usa un estándar de 900 px de contenido, con contenedor de 980 px incluyendo padding. Centrar el contenedor en el espacio disponible entre menú y chat usando sus reservas existentes; en escritorio, extender el fondo del menú lateral hasta dejar 24 px antes del marco de lectura. Mantener las transiciones y la adaptación móvil. Encabezado, introducción, párrafos, listas y tablas ocupan el ancho de lectura, sin límites interiores de 780/820/940 px. CertiTube conserva sus reglas propias. Al ampliar lectura, comprobar al final de página que el botón flotante del chat no cubra los enlaces siguiente/anterior; reservar espacio inferior hasta 1850 px con menú abierto y 1580 px con menú plegado.
- Reuse layout.mjs, existing theme tokens and native dialogs for new course/page controls. Keep lesson completion as a rounded button with its toggle inside: gray while pending, red when completed, with Sin Completar while pending and Completado when completed. Keep confirmation actions Cancelar/Aceptar without decorative icons; focus the dialog heading initially, preserve keyboard-visible focus and return focus to the trigger. Do not globally remove outlines to hide touch autofocus.
- Courses retain smooth desktop content accommodation when opening CertiChat; reduced motion removes the transition. From 1024px, CertiTube follows Cognee geometry with chat open and the centered CertiQuiz width with chat closed, as specified below. CertiChat retains its open/closed state when navigating within the same tab, including history restoration, and is pinned open on its explorer page. A manual close stays closed on later pages. Only completed explorer responses show the red hover border. Bind non-bubbling pointer enter/leave directly and idempotently to each real answer bubble when rendering/restoring; delegated shadow-root capture was unreliable in Chrome. Pointer hover selects their evidence without moving the camera and repeats the red pulse until the pointer leaves; click or Enter/Space centers the evidence, while links retain normal navigation. Selecting a concept repeats expanding, fading waves around that node; a fixed ring remains only for reduced motion. Reduced motion omits camera and pulse animation; hiding the page or using map controls stops repetition.
- Graph highlights and floating-card links come only from validated current evidence, never keyword/name matching or invented references. CertiTube source nodes, relationships sharing the same video source, and their waves use blue; guide evidence stays red. Shared concepts with video evidence use blue. Keep a compact color legend matching the zoom badge, and red border/icon hover on enabled map controls, send and concept-tag lines. All sourced answers expose the accepted guide links. Browser transcript metadata is untrusted and bounded; restoration never sends a paid request. Do not simplify away restoreChat validation to improve a complexity counter.
- On mobile, hide the footer's Developed by segment and keep the launcher outside visible footer text using the existing responsive layout. Test viewport and keyboard geometry rather than relying on desktop dimensions. Preserve course/quiz/chat storage isolation and memory fallback when storage is blocked.

## Diagram design

- Before creating, editing or reviewing a teaching diagram in any course, follow [diagram-design.md](diagram-design.md). It defines the shared design criteria, palette, authoring dimensions and review process directly; course assets and historical chats are evidence, not prerequisites for applying the rule.
- Improve that same guide during diagram work when the user establishes a general criterion or a design defect recurs with supporting evidence. Follow its improvement procedure, replace superseded guidance and record the rationale in [improvement-log.md](improvement-log.md). ## Validation and architecture

- Browser releases must version CSS/JS entry points and their shared static/dynamic imports together; verify a warm-cache reload of the published site, not only local output.
- Run npm run build, npm test and npm run check for source changes, including heading-only edits. The checker covers catalog-defined coverage, questions, diagrams, paths and anchors. npm test deliberately uses Node's in-process runner because default isolation hits spawn EPERM in this Windows sandbox; tests must restore changed globals.
- Use isolated playwright-cli sessions and the existing smoke scripts without screenshots. After changing viewport size, wait for the target layout predicate with waitForFunction before asserting geometry: course content and footer animate their margins across breakpoints. Select the affected course smoke plus diagram-check.cjs for SVG work; CertiChat has general, explorer, mobile and anchor-navigation checks. Run API/PostgreSQL suites through each service's documented isolated test mode when its contract changes; ordinary tests mock external providers.
- Deep Chat smoke fixtures must seed history before reloading the module and reset the isolated profile's open/reference state. Compare rendered textContent with newline-normalized transcript text; HTML br elements do not preserve newline characters there.
- For initial geometry on timestamped routes, reload when the exact URL is already active; navigating to the same fragment may retain the old document and native scroll position. Measure chapter transitions at the current width instead of assuming particular titles produce different heights; still verify text fade and cancellation.
- Pre/postflight must scan the full working source via their isolated Git index/object directories under output/, preserving real staging and cleaning scratch in finally, including failed scans. A tracked-only MCP pass omits new files. Future tasks baseline the working application; never replace a failed baseline or weaken rules to hide degradation. Preserve intentional tradeoffs and actual validation in improvement-log.md.
- .sentrux/rules.toml is authoritative. Installed Sentrux 0.5.7 layer order is tests 0 → entry 10 → adapters 20 → domain/security 30; executable fixtures verify it. The Python plugin currently resolves absolute imports only; relative-import edges are not fully covered. The MCP rule result is limited to three checks, so use the CLI for all configured rules. Run scripts/check-architecture-rules.ps1 after tool upgrades or rule edits. Graphify's optional SQL parser is unavailable; isolated PostgreSQL tests validate persistence.


## Acuerdos para fichas de CertiTube

Esta sección recoge los acuerdos del usuario del 14 de octubre de 2026. Aplicarla al generar o revisar las fichas Markdown, junto con la plantilla y límites de [docs/certitube.md](../docs/certitube.md).

- Generar una sola ficha en data/certitube/<videoId>/<videoId>.md, con JSON inicial y las secciones Resumen, Capítulos y Recursos relacionados. La misma fuente alimenta página, búsqueda y evidencia. Mantener videoId, ruta, addedAt y anclas estables; conservar borradores hasta verificar descripción, recursos, duración y tiempos contra las fuentes del autor.
- Usar el título revisado aprobado por el usuario, con redacción natural, sin prefijos redundantes ni una raya editorial impuesta. El título aprobado de MWASexQNDVU es AI Data Platform Workbench for VS Code Community Edition. No exigir que la ficha copie literalmente el título de YouTube ni alterar los nombres oficiales de productos dentro de la explicación.
- En Resumen, separar la pregunta inicial y la explicación con una línea en blanco; usar párrafos breves y completos. Todo el resumen alimenta los metadatos y debe caber en 1.500 caracteres. No perder los párrafos posteriores al primero ni inventar capacidades o hechos.
- Escribir solo segmentos con tiempos verificados. Si no hay segmentos, conservar únicamente 00:00 — Video completo como sección de evidencia: la página oculta su barra y explicación duplicada, pero mantiene #t-0 operativo. Los videos segmentados muestran una única explicación seleccionada y sus enlaces abren el segundo exacto.
- Escribir recursos como enlaces Markdown con un título completo y claro, sin puntos finales sueltos. No acortar el texto de origen ni las URLs para simular puntos suspensivos. El render muestra cada recurso en una sola línea con elipsis, título completo al pasar el mouse e icono de enlace delante, usando el color principal del tema.
- No insertar HTML, SVG, estilos, controles de reproducción o bloques duplicados en las fichas. Reutilizar el render compartido: encabezado compacto, reproductor, Resumen, capítulos cuando existan y Recursos relacionados. Omitir los bloques retirados Caso de uso y Arquitectura. Desde 1024 px, el conjunto de reproductor y lista y el bloque Cognee tienen un máximo de 1.200 px, incluso con CertiChat abierto. Con el chat abierto, centrar ambos paneles juntos, con columna de chat de 420 px, separación de 24 px y margen exterior mínimo de 24 px. Mantener inicio 20 px bajo el encabezado y alto mínimo 460 px usando la fórmula de ventana del explorador. Con CertiChat plegado, centrar el conjunto con los mismos márgenes adaptables que la navegación de CertiQuiz, sin reservar una columna vacía. El chat usa el mismo rectángulo que el de la página del grafo. El título de Resumen permanece visible sobre su texto desplazable. Si no hay capítulos, el resumen usa la altura disponible y Recursos relacionados queda al final; solo aparece scroll cuando el contenido ya no cabe. El foco automático de una cita no añade un borde exterior rojo al contenedor; los controles conservan el foco visible de teclado. En móvil la tarjeta mantiene altura natural.
- El subtítulo del reproductor dice solo CertiTube. La lista de videos es una tarjeta con encabezado CertiTube (Tube en rojo) y subtítulo Videoteca en el formato de CertiChat, borde superior rojo y alineación con el reproductor en escritorio. Su columna se adapta de 300 a 360 px y las miniaturas de 120 a 144 px cuando hay espacio, reduciendo el reproductor dentro del mismo ancho total centrado. Cada fila tiene el gris de las respuestas del chat, sin borde visible por defecto; hover añade solo borde rojo. Mostrar como máximo tres líneas del nombre con elipsis y conservar el nombre completo en el enlace. No repetir ordinal ni AI CloudTech debajo de cada nombre. Los títulos de capítulos se escriben en las fichas con capitalización de oración y se muestran sin transformarlos a mayúsculas.
- CertiChat titula sus fuentes Recursos Relacionados y las presenta con una línea, elipsis, título completo y texto/SVG del color principal del tema. Clasificar el SVG por la URL validada: curso de CertiTips, video de CertiTube y enlace genérico para otros destinos admitidos. Aplicar iconos al completar el streaming y al restaurar historial, sin otra consulta ni cambios a la validación de fuentes. El bloque Abrir chat del sitio publicado permanece retirado de la vista local.
- La leyenda del grafo muestra los SVG de curso y video junto a CertiTips y CertiTube, conservando sus colores rojo y azul. La tarjeta de concepto tiene borde rojo y una línea del mismo grosor desde su parte inferior hasta el nodo seleccionado. Sus fuentes actuales usan SVG, una línea, elipsis y título completo; no inferir referencias por nombre o palabras clave.
- El encabezado mantiene iconos cuadrados CertiQuiz, CertiTube y CertiChat antes de Search. CertiChat usa el mismo SVG de cerebro y destino /certichat/ que la acción Ver el grafo de CertiChat. El botón móvil de grupos comparte el fondo y formato de esos accesos, con borde/icono rojo al pasar el mouse. Conservar foco visible y comprobar que no desborden los anchos móviles.

- Los enlaces compartidos usan assets/icons/share-logo-square.png como imagen Open Graph pública de 512×512, con fondo rojo opaco hasta las cuatro esquinas. Conservar los píxeles del logo original; no reutilizar como preview el favicon con esquinas transparentes. Mantener favicon y logo de navegación independientes de este formato. Verificar metadatos, opacidad y esquinas sin capturas ni enviar mensajes de prueba por Slack.
