# Local Codex Policy for CertiTips

This file supplements the global policy with repository-specific rules. The root README presents the product and courses; contributor instructions belong in docs/courses.md, service operations in service READMEs, and executable checks in [validation.md](validation.md). Experiments and detailed audits belong in ignored output/.

## Source and runtime boundaries

- CertiTips publishes Spanish study guides at /certitips/ in jgangini/certitips. Use Node.js 24, the existing Markdown build and shared browser modules. CertiQuiz and CertiChat are independent optional APIs; do not import server code into browser/build code or add a frontend framework.
- data/catalog.json is the course/page inventory. data/<code>/ is the single course source directory: NN_name/NN_name.md and its img/ contain course text and images, alongside questions.json, coverage.json and authoring specifications. assets/icons/ holds global reusable icons, medals and favicons, regardless of which course introduced them. Preserve Lucide's manifest, exact geometry and ISC AND MIT notices. Preserve user-provided originals in data/CDMP-DMF/diagram-sources/ without changing their bytes or inventing a license.
- Derive numbered module names from modules followed by resources; overview is 00_empieza_aqui. contentDir and route use the course code; page.file locates the Markdown independently of its public slug. Stable course.id, page slugs, question IDs and source IDs preserve progress and evidence. Publish only current code/module routes, with overview/ as the course entry; do not generate legacy aliases or redirect pages. Keep section fragments working.
- Resolve contentDir beneath data/; do not recreate a parallel content/ tree. The site publishes only catalog-listed modules and their img/ assets, not the entire data/ directory. Keep CertiQuiz's Docker/deployment allowlist restricted to catalog and question banks.
- CertiQuiz discovers banks through catalog.courses[].questionBank. Author each bank once at data/<code>/questions.json and register it as <code>/questions; never maintain a second bank or copy it manually to the VPS. Preserve GitHub refresh, last-valid-catalog fallback and existing-room snapshots. Before publishing any catalog/bank or changing the API contract, run `npm run check:certiquiz` (Python 3.12, no packages) plus build/test/check. The checker must reuse services/certiquiz/app/catalog.py; do not duplicate the API schema in another validator. Keep the check mandatory in Pages CI and the CertiQuiz Docker build. A rejected bank must block publication/build, not disable validation or replace the live catalog. See services/certiquiz/README.md for limits; practice availability still requires a quiz.md source.
- dist/ is generated and replaced on build. output/, graphify-out/, caches and .private/ are not published sources. Keep transcripts outside this repository. data/certichat-graph.json is the public projection, not another lesson collection; native Cognee stores and credentials remain private.
- Corpus documents include introductions, anchored sections and explained questions, so their count exceeds the Markdown count. Source-file moves alone do not reduce index size. Reuse an index only when the complete IDs, titles, course IDs and text hashes match; resolve citations from the current validated manifest. Never modify open native stores to change URLs.

## Course editing

- Address the learner directly in Spanish. Catalog metadata supplies H1; chapters use H2/H3. Keep examples, exercises with closed details solutions, sources, glossary and practice in the established shared layout. Every technical H2 needs a specific teaching graphic whose mechanism matches the lesson, not a generic row of text cards.
- Internal links use {{base}} plus the public course code and slug. Module images use img/name.svg or img/name.png beside the Markdown. A heading change changes its anchor: update all references and rebuild/check. Keep image title/description, alt text and caption coherent; the caption explains meaning rather than repeating the title.
- Practice pages use exactly Práctica and Pon a prueba lo que entiendes as page metadata. The entry and results use the red PRÁCTICA eyebrow and compact CertiQuiz heading; the entry keeps its 4px red top border, question/domain counts and right-aligned Comenzar button below a separator. Disable Siguiente until an option is selected. Results show the score, a question table and neutral per-area totals, with reset/exit controls at the top right; both controls confirm before clearing an attempt. Do not restore removed advice, follow-up links or bottom actions. Truncate question rows with ellipsis and expose their full text on hover; clicking opens read-only answer detail with Resumen beside Siguiente and no duplicate answer-status line.
- Questions have four stable options, one correct answer, its explanation and a real section reference. When a supplied quiz.md is the source, translate the complete question, ordered alternatives and Rationale; use Correct Answer, never Selected Answer. Do not replace the rationale with an original summary or invent explanations for distractors: their explanation string may be empty. Give translated questions new stable IDs tied to source numbering and keep source hash/mapping privately. Six questions per technical module remains the default for original banks; a source-sized bank declares exact questionCounts for every technical module in the catalog, at least two per domain. Keep two per module per attempt and preserve the original completed attempt during review. Course sampling and study targets are not official exam weightings or pass marks.
- Data Management Fundamentals (CDMP-DMF) is the DAMA applied course, not an Oracle certification. Its titles and navigation capitalize significant words, leaving articles/prepositions/conjunctions lowercase except at the beginning. Use full official product names in prose, diagrams and questions, without shortening them to AIDP, OAC, EDM or OCI; preserve technical identifiers and URLs exactly.
- Before changing Oracle capabilities, research both Slack product discussion and current public Oracle documentation, release notes and lifecycle notices. Record date, evidence, scope and status privately: available, Preview, implemented extension or announced. Preview is usable within documented scope; an announcement is not availability. Published lessons cite public sources, use fictional cases and explain actual constraints beside the capability.
- Consult supplied DAMA material selectively; book/chapter/page traceability stays in .private/, never the public lessons, diagrams, questions or coverage. Keep instructor agendas, duration estimates and internal course-selection policy out of learner content. Governance centers on Oracle AI Data Platform and Oracle Autonomous AI Lakehouse; do not recommend standalone OCI Data Catalog for new designs. Distinguish catalogs, source identities and policies; never imply automatic synchronization or propagated authorization without evidence.
- Verify each exam edition/language before changing exam numbers or conditions. The October 2026 review confirmed the 40-question/60-minute/65% values publicly for the Japanese 1Z0-1085-26-JPN and 1Z0-1122-26-JPN variants, not independently for every language. Do not promote that historical evidence into a universal verification claim.

## Shared interface components

- Reuse layout.mjs, existing theme tokens and native dialogs for new course/page controls. Keep confirmation actions Cancelar/Aceptar without decorative icons; focus the dialog heading initially, preserve keyboard-visible focus and return focus to the trigger. Do not globally remove outlines to hide touch autofocus.
- CertiChat retains its open/closed state when navigating within the same tab, including history restoration, and is pinned open on its explorer page. A manual close stays closed on later pages. Only completed explorer responses show the red hover border. Pointer hover selects their evidence without moving the camera and repeats the red pulse until the pointer leaves; click or Enter/Space centers the evidence, while links retain normal navigation. Selecting a concept repeats expanding, fading waves around that node; a fixed ring remains only for reduced motion. Reduced motion omits camera and pulse animation; hiding the page or using map controls stops repetition.
- Graph red nodes/edges and floating-card links come only from validated current evidence, never keyword/name matching or invented references. All sourced answers expose the accepted guide links. Browser transcript metadata is untrusted and bounded; restoration never sends a paid request. Do not simplify away restoreChat validation to improve a complexity counter.
- On mobile, hide the footer's Developed by segment and keep the launcher outside visible footer text using the existing responsive layout. Test viewport and keyboard geometry rather than relying on desktop dimensions. Preserve course/quiz/chat storage isolation and memory fallback when storage is blocked.

## Diagram design

- Before creating, editing or reviewing a teaching diagram in any course, follow [diagram-design.md](diagram-design.md). It defines the shared design criteria, palette, authoring dimensions and review process directly; course assets and historical chats are evidence, not prerequisites for applying the rule.
- Improve that same guide during diagram work when the user establishes a general criterion or a design defect recurs with supporting evidence. Follow its improvement procedure, replace superseded guidance and record the rationale in [improvement-log.md](improvement-log.md). Do not create competing per-course standards or turn a one-image adjustment into a universal rule.

## Validation and architecture

- Browser releases must version CSS/JS entry points and their shared static/dynamic imports together; verify a warm-cache reload of the published site, not only local output.
- Run npm run build, npm test and npm run check for source changes, including heading-only edits. The checker covers catalog-defined coverage, questions, diagrams, paths and anchors. npm test deliberately uses Node's in-process runner because default isolation hits spawn EPERM in this Windows sandbox; tests must restore changed globals.
- Use isolated playwright-cli sessions and the existing smoke scripts without screenshots. After changing viewport size, wait for the target layout predicate with waitForFunction before asserting geometry: course content and footer animate their margins across breakpoints. Select the affected course smoke plus diagram-check.cjs for SVG work; CertiChat has general, explorer, mobile and anchor-navigation checks. Run API/PostgreSQL suites through each service's documented isolated test mode when its contract changes; ordinary tests mock external providers.
- Pre/postflight must scan the full working source via their isolated Git index/object directories under output/, preserving real staging and cleaning scratch in finally, including failed scans. A tracked-only MCP pass omits new files. Future tasks baseline the working application; never replace a failed baseline or weaken rules to hide degradation. Preserve intentional tradeoffs and actual validation in improvement-log.md.
- .sentrux/rules.toml is authoritative. Installed Sentrux 0.5.7 layer order is tests 0 → entry 10 → adapters 20 → domain/security 30; executable fixtures verify it. The Python plugin currently resolves absolute imports only; relative-import edges are not fully covered. The MCP rule result is limited to three checks, so use the CLI for all configured rules. Run scripts/check-architecture-rules.ps1 after tool upgrades or rule edits. Graphify's optional SQL parser is unavailable; isolated PostgreSQL tests validate persistence.
